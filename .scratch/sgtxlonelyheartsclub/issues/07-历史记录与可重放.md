## Question

**历史记录子页面**的数据与交互设计（已定：记录上传模组 + 生成剧本，可重放演示）。

**现状锚点**：campaign 目前纯内存（`state.campaigns[id]`），`/api/campaigns/<id>` 可读单份；前端 `loadCampaign` 支持 live 路由 + 静态 campaign.json 兜底；`run-module.sh` 产物落 `data/output/<campaign.json>`。

**子问题**：
1. **数据记录**：SQLite（关联 02 的存储设计）记录哪些字段——上传模组（文件名/hash/时间/解析状态/识别出的实体）、生成剧本（campaign id/title/rules/eval 分数/LLM 用况/时间）；是否需要版本（同一模组多次生成）。
2. **列表页交互**：历史列表的呈现（卡片/表格/时间线）、筛选（按规则 COC/DND、按类型模组/剧本）、搜索（是否接 RAG）。
3. **可重放机制**：campaign.json 快照 + 前端 playback（剧本逐幕/逐场景播放，参考站 pager/逐词动效语感）——静态快照重放 vs live 重放；playback 的 UI 形态（进度条 + 节点图高亮 + 详情面板）。
4. **demo 路径**：历史列表 → 打开剧本 → 播放；无需重新生成即可演示（这是「随时可访问」的核心 demo 面）。

**产出**：历史记录 schema + 列表/详情/播放三态 UI 规格。

➡️ 推荐：SQLite 两张表 `modules`（模组元数据）+ `campaigns`（剧本元数据+eval）；playback 用 campaign.json 静态快照 + 前端播放器（逐事件节点高亮 + 详情面板动效），不依赖 live 生成。
