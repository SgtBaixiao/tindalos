## Question

SgtXLonelyHeartsClub **前端技术栈与首页栏目入口**如何落地，把 aicodingdictionary 的纸墨设计/动效复刻为「各栏目入口」？

**现状锚点**：Tindalos 前端是 React 19 + React Flow(xyflow) 12 + Zustand + Vite 8（`frontend/`），已有「剧本节点图」（Act/Scene/Event/Npc/Clue 节点）+ NodeDrawer + ProgressBand + `live.ts`（SSE 实时生成）。参考站是 Next.js/Turbopack + Three.js r184 3D 知识图谱 + CSS-modules，其 UI 是「纸墨双色 + cubic-bezier(.16,1,.3,1) + stagger 揭示」的极简体系。

**子问题**：
1. **技术栈取舍**：延续现有 React+Vite 并把参考站设计体系作为共享 CSS/组件层（推荐），还是新建 Next.js 站点？——现有 `live.ts`、React Flow 节点图、SSE 流都是 Vite 资产，迁移 Next.js 代价大。
2. **首页入口形态**：参考站 3D 知识图谱映射为「栏目节点图」（React Flow 已有图能力，栏目=节点、子功能=子节点、点击开详情面板——天然贴合参考站的 node-detail 面板），还是简化为纯 CSS 动画卡片网格？
3. **复刻深度**：design-spec.md 的 14 个 keyframes（wordFall 逐词坠落、revealFade 52ms stagger、pagerRoll 1.3em 裁切上滚、面板 1/3 屏宽 + canvas 让位）哪些照搬、哪些适配为栏目语义（loading 屏 → 站点名 SgtXLonelyHeartsClub 逐词升起；pager → 栏目切换）。
4. **栏目清单**：剧本工作台 / 模组资料库 / 规则问答 / 历史记录 四个栏目 + 各栏目入口的缩略呈现。

**产出**：一个可点击的原型（首页 + 一个栏目详情），用户对设计/动效/信息架构做反应。参考 `.scratch/sgtxlonelyheartsclub/design-spec.md`。

➡️ 推荐：延续 React+Vite；栏目入口用图式（React Flow 或轻量自定义 SVG 图）+ 复刻设计 tokens 与核心动效；loading 屏用站点名逐词坠落签名动效。
