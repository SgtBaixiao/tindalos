## Question

**多模态识别管线**（qwen3-vl-plus 全自动识别 + 置信度门槛 + 人工确认 UI）的具体流程设计。

**已定**：模型选型 qwen3-vl-plus（阿里云 DashScope，输入 ¥1/M、输出 ¥10/M，单张 1024×1024 ≈ 1026 tokens ≈ ¥0.005/张，全模组 <¥0.5）；全自动 + 人工确认兜底（研究确认「头像错配必有」，确认 UI 是必需而非可选项）。

**子问题**：
1. **识别管线顺序与容错**：图注对齐（图 → 页内邻近文本 → 全篇名字典）→ 人脸检测（OpenCV Haar）粗筛 + VL 验证（头像）→ 地图检测（HoughLinesP 线条密度）→ 地点绑定。各环节的失败/低置信度如何降级（跳过？进人工确认？）。
2. **提示词与输出契约**：qwen3-vl-plus 每次调用喂什么（单图 + 上下文文本切片 vs 批量）、输出 JSON schema（实体名/类别/置信度/对齐依据）、low-detail 压缩策略。
3. **置信度门槛**：门槛值定多少，低于门槛进人工确认队列；跨图同实体如何合并（同名去重 + 冲突仲裁）。
4. **人工确认 UI**：低置信度项列表确认（推荐）还是画布点选？确认结果如何回流进数据模型（落 SQLite？）——关联 01 前端、06 数据模型。
5. **成本控制**：上下文缓存、结果缓存（同一模组重复上传不重跑）、批处理。
6. **依赖**：图像来源由 03 的提取方案提供（阻塞）。

**产出**：识别管线状态机 + 提示词/输出契约初稿 + 人工确认交互规格。

➡️ 推荐：管线顺序「图注对齐 → Haar 粗筛 → VL 验证（仅对候选图调用，省 token）→ 地图检测 → 地点绑定」；低于阈值进确认队列，确认结果写 SQLite `entity`/`entity_mention`；结果缓存 key = 文件 hash + 页号。
